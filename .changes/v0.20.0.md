## [0.20.0] - 2026-11-20

### Added

- `zinder-bench lightwalletd-wallet-load` can now read distinct tree-state frontiers, report `GetSubtreeRoots` observations, mix `GetTransaction` and transparent-address reads with supplied or discovered transaction IDs, and connect through a private-CA TLS proxy by virtual host. All new flags are opt-in, and existing workloads and report fields are unchanged. ([#328](https://github.com/ZcashFoundation/zinder/pull/328))
- When native `CompactBlocksInRange` refuses a stream because the server already serves its open-stream limit, the `RESOURCE_EXHAUSTED` status now carries the `COMPACT_BLOCK_STREAM_LIMIT_REACHED` error reason, and `zinder-client` classifies it as retry-with-backoff. Clients that do not know the reason keep their current handling. ([#335](https://github.com/ZcashFoundation/zinder/pull/335))
- `zinder-query` and both `zinder-compat-lightwalletd` serving modes now serve the standard `grpc.health.v1` service on their wallet listeners, so gRPC load balancers and Kubernetes `grpc` probes can check a listener directly. `Check` and `Watch` report `SERVING` exactly when `/readyz` admits traffic, report `NOT_SERVING` once shutdown begins, and need no bearer token. Reflection lists the service. ([#340](https://github.com/ZcashFoundation/zinder/pull/340))
- Behind the reference Caddy proxy, one wallet could hold enough receive slots to get other wallets refused with `UNAVAILABLE`. New `trust_proxy_client_address` settings for query, compat, and explorer key receive-slot fairness on the `x-zinder-client-address` header the Caddy template now sets; leave them off unless every path to the listener goes through that proxy, as the TLS runbook describes. Every runtime now folds buffered histogram samples on a five-second schedule, so an unscraped `/metrics` endpoint no longer grows with traffic, and receive pools export `zinder_grpc_request_receive_slots_held`. ([#341](https://github.com/ZcashFoundation/zinder/pull/341))
- Ingest now re-verifies every settled tree-state checkpoint in paced background cycles (25 rows per second by default). A damaged row parks ingest readiness and is reported in `CanonicalControl.WriterStatus` through the new `canonical_store_damaged` field and readiness cause, so `zinder-query` and `zinder-compat-lightwalletd` refuse wallet traffic with `canonical_store_damaged` until a later check clears it, and the single-volume entrypoint treats it as a park instead of restarting. The damage survives restarts. The bulk loader now refuses a checkpoint whose frontiers do not match the pools active at its height. Readers built before this change ignore the new field. ([#343](https://github.com/ZcashFoundation/zinder/pull/343))
- Wallet-mode `zinder-compat-lightwalletd` now answers `GetStandardFee` with the fee and estimator version its verified node reports through `getstandardfee`, instead of `UNIMPLEMENTED`, using the same endpoint admission and failover as `SendTransaction`. A zero fee or a malformed node reply returns `INTERNAL`, as Go lightwalletd v0.6.2 does. Compact-blocks serving and deployments without a node still answer `UNIMPLEMENTED`, and a node outage now also makes `GetStandardFee` fail with `UNAVAILABLE`. ([#344](https://github.com/ZcashFoundation/zinder/pull/344))
- Browser wallets can use gRPC-Web on the lightwalletd endpoint when their site is listed in `compat.browser_origins`. The same endpoint continues to serve native gRPC. ([#357](https://github.com/ZcashFoundation/zinder/pull/357))
- Run paired benchmark campaigns with matched work checks, input digests, and raw reports. Wallet-load reports distinguish checkpoint reads from tree-state rebuilds. ([#391](https://github.com/ZcashFoundation/zinder/pull/391))
- Ingest and the wallet projector report RocksDB write pressure and per-level SST counts. Query and lightwalletd report shared cache use and cumulative read statistics across serving generations. ([#406](https://github.com/ZcashFoundation/zinder/pull/406))
- Wallet-serving metrics now report requests refused before handlers run, stream outcomes, and per-process memory. The reference Compose alerts identify missing scrape targets. For the distribution of updates returned per ingest segment, use `zinder_ingest_source_segment_updates`. The configured limit remains available as `zinder_ingest_source_segment_max_blocks`. ([#415](https://github.com/ZcashFoundation/zinder/pull/415))
- Operators can replay retained events to measure when a wallet reader first published a committed block. Publisher slot waits and ingest subtree verification outcomes now report elapsed time, including time spent rechecking a disagreement. ([#417](https://github.com/ZcashFoundation/zinder/pull/417))

### Changed

- Zinder now requires Rust 1.100.0 (up from 1.95.0) across the workspace and published SDK crates (`zinder-core`, `zinder-proto`, and `zinder-client`), upgrades its Rust crate dependencies (including `hmac` 0.13, `sha2` 0.11, `parking_lot` 0.13, `rust-rocksdb` 0.54.1, `tokio` 1.54.1, `tonic` 0.14.9, `prost` 0.14.6, `zcash_primitives` 0.31.1, and `zcash_transparent` 0.11.1), and advances vendored `lightwallet-protocol` from v0.5.0 to v0.6.0. Bundled container and Compose defaults update to Rust 1.100.0 / Debian Bookworm, reference `lightwalletd` v0.6.2, PostgreSQL 18.7, Prometheus v3.16.0, and Grafana 13.3.1. ([#326](https://github.com/ZcashFoundation/zinder/pull/326))
- Tree-state reads at a height with a stored checkpoint no longer recompute each pool's commitment-tree root, which cost several milliseconds of CPU per three-pool request. Checkpoints are validated when they are written and protected at rest by RocksDB block checksums. In `zinder-core`, `CommitmentTreeFrontiers::from_validated_parts` now returns a `Result` and rejects a frontier validated for another pool, and frontier equality includes the pool. ([#330](https://github.com/ZcashFoundation/zinder/pull/330))
- Compact-block range reads, which serve `GetBlockRange` and tree-state rebuilds, now read one stored row per block instead of two, cutting storage reads for wallet block streams. ([#331](https://github.com/ZcashFoundation/zinder/pull/331))
- Tree-state densification now stores a checkpoint for every settled block by default, so tree-state requests no longer rebuild state from compact blocks once a stride is complete. The first start after upgrading fills the missing rows once; the Mainnet cost is estimated at about 2.4 GB of rows before compression and 4 to 5 CPU-hours. To keep the smaller `commitment-budget` selection, set `ingest.tree_state_densification.selection` before the first upgraded start, because switching later keeps the rows already written. ([#332](https://github.com/ZcashFoundation/zinder/pull/332))
- Compact-blocks `zinder-compat-lightwalletd` now judges the tip's age for `GetLatestBlock` and `GetLightdInfo` after reading the tip header rather than when the call arrives, so a slow read can refuse a tip that was fresh on arrival but never serves one that expired. `zinder-bench rocksdb-compact-block-range` reports also measure each range through the serving reader, under a new `canonical_reader` section in report format version 3. ([#345](https://github.com/ZcashFoundation/zinder/pull/345))
- `GetBlockRange` and `GetBlockRangeNullifiers` streams now open after a first read of at most 256 KiB of stored compact blocks instead of up to 1,000 blocks and 2 MiB, and each later chunk is read while the one before it is sent, holding at most two chunks per stream. A descending range that runs below retained history now sends every height checked before it ends with `NOT_FOUND`. A pre-stream `UNAVAILABLE` or `DATA_LOSS` now applies only to blocks the first read reaches. ([#347](https://github.com/ZcashFoundation/zinder/pull/347))
- Lightwalletd block-range responses spend less time converting compact transactions when a wallet requests only shielded pools or nullifiers. ([#358](https://github.com/ZcashFoundation/zinder/pull/358))
- Native ChainEvents contract revision 10 resumes a pruned reorg with one replacement through the current tip. Apply the replacement before discarding undo state through its settled tip, then save its cursor to receive later events. On server revisions 8 and 9, the Rust SDK reports a synthesized reorg as an expired cursor. Rebuild from the earliest retained event. ([#395](https://github.com/ZcashFoundation/zinder/pull/395))
- RocksDB writers honor the configured write-buffer limits for the default column family. Update log filters from rocksdb_direct_io_unsupported to rocksdb_direct_io_open_failed for direct I/O errors that trigger a buffered retry. ([#405](https://github.com/ZcashFoundation/zinder/pull/405))
- Native wallet queries batch complete 1,024-root subtree pages to reduce read latency. ([#408](https://github.com/ZcashFoundation/zinder/pull/408))

### Fixed

- The lightwalletd-compatible `GetSubtreeRoots` now streams every remaining subtree root when `maxEntries` is 0, instead of stopping at 1,000 roots with an `OK` status. Mainnet has more than 1,100 Sapling subtrees, so wallets that requested every root received a truncated list. If the chain view a stream started on is retired mid-stream, the stream ends with a retryable `UNAVAILABLE`; retry from the original `startIndex`. ([#327](https://github.com/ZcashFoundation/zinder/pull/327))
- `zinder-compat-lightwalletd` now exits with status 1 and names the task when a background task, its operational endpoint, or a serving-generation teardown fails or ends early, as `zinder-query` does; previously it could keep serving wallet traffic without them. On shutdown, both runtimes now deliver `UNAVAILABLE` with the `shutting_down` readiness cause to calls still open at the drain deadline, waiting up to 2 more seconds, instead of leaving clients with `UNKNOWN` and a broken connection. ([#338](https://github.com/ZcashFoundation/zinder/pull/338))
- Zinder-to-Zinder gRPC dials and their automatic reconnects now give up after 5 seconds, covering name lookup, TCP, TLS, and the peer's whole initial HTTP/2 SETTINGS frame, so an unresponsive or stalled ingest, query, or explorer peer no longer holds a client for minutes. A peer that does not speak HTTP/2 fails the dial at once. `zinder-projector` and `zinder-compat-cipherscan` keep retrying a timed-out startup dial until the peer answers; a refused connection still exits. Dials no longer send an unauthenticated health request, so a proxy that drops unauthenticated streams no longer blocks startup. A peer that does not open with an HTTP/2 `SETTINGS` frame now fails the dial at once. Endpoint URLs in dial logs are redacted. ([#342](https://github.com/ZcashFoundation/zinder/pull/342))
- In compact-blocks serving, `GetBlock` by hash now answers a best-chain block whose compact block is missing with `NOT_FOUND` and `ARTIFACT_UNAVAILABLE`, as wallet serving does, instead of `BLOCK_NOT_IN_BEST_CHAIN`. In both modes, a `GetBlockRange` chunk holding a block that a lightwalletd message cannot carry now fails whole with `DATA_LOSS`: before the stream opens when it is the first chunk, and before any of its blocks are sent otherwise. ([#346](https://github.com/ZcashFoundation/zinder/pull/346))
- The reference Caddy configuration reuses up to 16 readiness connections, so concurrent wallet calls can be admitted while block ranges continue streaming. ([#356](https://github.com/ZcashFoundation/zinder/pull/356))
- Wallet-mode `GetBlockRangeNullifiers` returns only the requested shielded pools. Empty and transparent-only selections continue to return all shielded nullifiers. Selecting Sapling keeps transactions that have Sapling outputs and no Sapling spends. ([#359](https://github.com/ZcashFoundation/zinder/pull/359))
- Wallets can recover from an expired mempool event or snapshot page cursor. The Rust SDK reports `RefreshMempoolSnapshot`. Discard partial pages, take a fresh snapshot, and subscribe from its events resume cursor. Native contract revision 11 reserves the retired `BROADCAST_DISABLED` reason. Match `ENDPOINT_CAPABILITY_UNAVAILABLE` when broadcast is unavailable. Upgrade ingest and native query together because query requires a writer at its own revision. ([#393](https://github.com/ZcashFoundation/zinder/pull/393))
- Wallets following ChainEvents with an address filter continue to receive matching commits after long runs of quiet blocks. An idle subscription checks each quiet commit once, and matching events keep their usual resume cursors. ([#397](https://github.com/ZcashFoundation/zinder/pull/397))
- Transparent address lookups now report a protocol mismatch when the node returns a balance or an unspent output as an array of values in field order. ([#399](https://github.com/ZcashFoundation/zinder/pull/399))
- Wallets can use RPC-order block hash bytes to look up a tree state. Unary nullifier responses retain transparent-only transaction IDs, and mempool suffix exclusions preserve transactions whose IDs also match in another pool. ([#400](https://github.com/ZcashFoundation/zinder/pull/400))
- Clients using gRPC reflection v1alpha can now discover `CompactTxStreamer` and retrieve its message definitions from the lightwalletd endpoint in wallet and compact-blocks modes. ([#401](https://github.com/ZcashFoundation/zinder/pull/401))
- Wallets can send up to 20,000 transaction ID suffixes in one GetMempoolTx request, matching Go lightwalletd v0.6.2. ([#402](https://github.com/ZcashFoundation/zinder/pull/402))
- Both lightwalletd nullifier RPCs return chain metadata with zero tree sizes. Unrecognized numeric pool filters select no transaction components, so range requests still return every block and mixed filters return the recognized pools. ([#403](https://github.com/ZcashFoundation/zinder/pull/403))
- Canonical and materialized-view store admission uses less memory when validating an existing RocksDB store. ([#404](https://github.com/ZcashFoundation/zinder/pull/404))
- Wallet supervision checks the query and lightwalletd gRPC listeners before admitting traffic. Configured node readiness floors apply whenever the HTTP probe is absent or unreachable, and a failed poll clears the previous upstream sync observation. Rust callers reading the resolved node health address must handle an optional value. ([#416](https://github.com/ZcashFoundation/zinder/pull/416))
