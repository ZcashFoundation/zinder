## [0.19.0] - 2026-11-19

### Added

- The single-volume `zinder-wallet-serving` image now also serves the lightwalletd `CompactTxStreamer` protocol on port 9067, so one image, one container, and one volume give wallets both the native `WalletQuery` service on 9102 and lightwalletd compatibility. `zinder-wallet-serving-explorer` serves it too. The entrypoint starts `zinder-compat-lightwalletd` with `zinder-query` once the wallet projection is ready and supervises it the same way; its operational endpoint listens on `[::]:9107`, like query's 9106, and the image healthcheck now requires both readers. Compatibility is on by default, so publish 9067 behind a TLS proxy to serve lightwalletd clients, and set `ZINDER_WALLET_SERVING__LIGHTWALLETD=false` to keep it stopped on a host without memory for a second reader; its memory has not been measured in this image, and the wallet-serving runbook says what to measure before relying on 8 GB. `ZINDER_COMPAT__*` variables, such as `ZINDER_COMPAT__MAX_CONCURRENT_BLOCK_RANGE_STREAMS`, reach the compatibility process alone. `ZINDER_STORAGE__SECONDARY_PATH` or `ZINDER_WALLET__SECONDARY_PATH` now stop the container at startup while compatibility runs, because both readers would share one secondary root. `zinder-compat-lightwalletd` now abandons gRPC calls still open 10 seconds after shutdown starts, as `zinder-query` does, so a slow block-range client no longer delays its exit. ([#297](https://github.com/ZcashFoundation/zinder/pull/297))
- Fresh construction now reports where its time goes. `zinder_ingest_canonical_construction_phase_duration_seconds{phase}` times picking the build tip, loading blocks, checking subtree roots and the tip against the node, and publication. `zinder_ingest_canonical_block_load_stage_duration_seconds{stage}` times each block on the loader, including idle wait (`receive_wait`) and commitment-tree hashing (the `tree_hashing_*` stages), and `zinder_store_canonical_block_load_stage_duration_seconds{stage}` and `zinder_store_canonical_block_load_finish_duration_seconds{step,family}` time the store's per-block work and its per-family finish. Construction also encodes each staged block value once instead of twice; stored data is unchanged. ([#315](https://github.com/ZcashFoundation/zinder/pull/315))
- `zinder-query` now reports tree-state replay work: replay depth, replayed note commitments per pool, stored versus replayed reads per 250,000-block height band, rebuild-slot admissions, slot wait time, and rebuild duration. The metrics reference lists the series. ([#316](https://github.com/ZcashFoundation/zinder/pull/316))
- Ingest now fills history built by a first sync with stored tree-state checkpoints in the background, so `GetTreeState` and `TreeStateAtHeight` at a settled height replay at most a bounded number of note commitments instead of up to 99 blocks. By default it stores a checkpoint each time 1,024 note commitments accumulate, an estimated 0.13 GB on Mainnet; `selection = "every-block"` stores one per block, an estimated 2.4 GB, so no read replays. Configure it under `[ingest.tree_state_densification]` (`ZINDER_INGEST__TREE_STATE_DENSIFICATION__*`), where `workers` (2) and `max_blocks_per_second` (500) bound its load. The pass starts once ingest follows the tip and, when Explorer views are enabled, they have caught up; it needs `ingest_control.listen_addr`, checks each 100-block stride against the stored checkpoint that ends it before writing, and resumes after a restart. Progress appears in the `zinder_ingest_tree_state_densification_*` metrics, where an `integrity_failure` outcome means stored history is damaged. ([#319](https://github.com/ZcashFoundation/zinder/pull/319))

### Changed

- The `zinder-ingest`, `zinder-projector`, `zinder-query`, `zinder-compat-lightwalletd`, and `zinder-explorer` images now run on a digest-pinned distroless base and are less than half their previous size. Each image checks its own health with the new `healthcheck` subcommand, for example `zinder-query healthcheck`, which requests `/readyz` and passes only on HTTP 200; add `--path /healthz` for liveness. The probe takes its address from `--addr`, then `ZINDER_OPS__LISTEN_ADDR`, then `[ops] listen_addr` in the `--config` file. These images no longer contain a shell, `curl`, or a package manager, so replace any custom healthcheck or script that runs `curl` or `sh` inside them with the subcommand, and inspect a running container with `docker exec <container> zinder-<runtime> --config /etc/zinder/config.toml --print-config`. All Zinder images now run as UID and GID 10001 instead of 1000, the UID the Zebra and Zakura images use, so they read the node's mode-0600 RPC cookie directly; `deploy/node-cookie-permissions.yml` is removed, and a running copy of that project should be stopped. Compose deployments and the single-volume images hand their volumes to UID 10001 on start. Give host files mounted into the containers, such as `/etc/zinder/control-secrets` and indexer TLS files, group 10001 before upgrading, and in other orchestrators chown volumes to 10001 or set `fsGroup: 10001`. Each per-service image ships a default `/etc/zinder/config.toml` that binds its operational and serving listeners to `[::]` and sets `allow_public_bind = true`, and its `CMD` passes that file, so `docker run -p` works with no listener settings. A file you mount at `/etc/zinder/config.toml` replaces the default as a whole, and arguments after the image name replace the `CMD`, so pass `--config /etc/zinder/config.toml` again to keep using the file. Other containers on the same Docker network can reach the default listeners without a published port, and host networking binds the host's interfaces, so run the containers on a dedicated network and avoid host networking, or set a listener to `127.0.0.1`. Ingest's control listener stays on `127.0.0.1:9100`. In Compose, `ZINDER_VERSION=vX.Y.Z` now pulls the signed release images of that tag; run `pull` and then `up -d --no-build` with the Compose file from the same tag, or leave `ZINDER_VERSION` unset and use `up -d --build` to build from source. The single-volume images keep `sh` and `curl`. Release images also carry OCI title, description, URL, documentation, vendor, and creation-time labels. ([#287](https://github.com/ZcashFoundation/zinder/pull/287))
- Fresh construction now builds to one reorg window (`ingest.reorg_window_blocks`, 1,000 by default) below the node's tip instead of to the tip, so a reorg of the node's newest blocks during a long first sync no longer discards the build. The first published settled tip is the same as before; ingest appends the newest window of blocks before it reports ready, so the first sync spends longer in catch-up. `ingest.run_overrides.target_height` still caps construction when it is lower, and the store then settles at that target. ([#315](https://github.com/ZcashFoundation/zinder/pull/315))
- A native tree-state request that needs a rebuild while every rebuild slot is busy now waits up to 2 seconds for a slot instead of failing at once; set the wait with `query.tree_state_replay_wait_ms` (`ZINDER_QUERY__TREE_STATE_REPLAY_WAIT_MS`, 0 to 5,000 ms). Up to 64 requests wait per rebuild slot by default (`query.tree_state_replay_waiters_per_slot`, `ZINDER_QUERY__TREE_STATE_REPLAY_WAITERS_PER_SLOT`, 1 to 256), and the rest still fail with `RESOURCE_EXHAUSTED` and `TREE_STATE_REPLAY_LIMIT_REACHED`. `zinder_query_tree_state_replay_refusals_total` gains a `reason` label, so alerts that match the unlabelled series need updating. Native `CompactBlocksInRange` now streams its range in 2 MiB reads, so the first block arrives sooner and memory per stream is bounded; each process serves at most 100 such streams and refuses more with `RESOURCE_EXHAUSTED`. ([#316](https://github.com/ZcashFoundation/zinder/pull/316))
- A lightwalletd `GetBlockRange` or `GetBlockRangeNullifiers` request past `compat.max_concurrent_block_range_streams` now waits up to 10 seconds for a slot and then fails with `UNAVAILABLE`, instead of failing at once with `RESOURCE_EXHAUSTED`, as lightwalletd does; at most as many requests wait as the limit has slots. A lightwalletd `GetTreeState` whose rebuild finds no free slot within `compat.tree_state_replay_wait_ms` (`ZINDER_COMPAT__TREE_STATE_REPLAY_WAIT_MS`, 0 to 5,000 ms, 2,000 by default) also fails with `UNAVAILABLE`, and one that finds every waiting place taken fails at once; `compat.tree_state_replay_waiters_per_slot` (`ZINDER_COMPAT__TREE_STATE_REPLAY_WAITERS_PER_SLOT`, 1 to 256, 64 by default) sets the waiting places per slot. Native `TreeStateAtHeight` keeps `RESOURCE_EXHAUSTED`. `zinder_compat_block_range_stream_refusals_total` gains a `reason` label, and new series time each block-range chunk's read, conversion, and wait for the client. ([#317](https://github.com/ZcashFoundation/zinder/pull/317))
- lightwalletd `GetLightdInfo.estimatedHeight` now reports the network height estimated from the served tip, as Zebra does, instead of the served tip itself. When the served tip is older than `compat.stale_tip_limit_ms` (`ZINDER_COMPAT__STALE_TIP_LIMIT_MS`, 25 minutes by default, 0 disables) and the writer cannot confirm it as its node's tip, because the node is unreachable, ahead of the writer, or shown behind by its peers, `GetLatestBlock` and `GetLightdInfo` fail with `UNAVAILABLE`, so wallets stop building transactions on a stale chain. A quiet chain's tip that the node still reports keeps answering, and every other call keeps serving stored data. Refusals are counted in `zinder_compat_stale_tip_refusals_total`. ([#318](https://github.com/ZcashFoundation/zinder/pull/318))
- Explorer's transaction-component and conventional-fee backfills and its transparent-address ranking build no longer derive note-commitment roots, which none of them use, so they no longer read compact blocks or replay tree states for that work. ([#320](https://github.com/ZcashFoundation/zinder/pull/320))

### Fixed

- Zinder's gRPC clients now negotiate TLS when a configured endpoint uses `https://`, such as the ingest-control address `zinder-compat-lightwalletd` and `zinder-projector` dial, or the wallet-query and explorer endpoints `zinder-explorer` and `zinder-compat-cipherscan` dial. Previously such an address opened a plaintext connection and could not reach a TLS server. `http://` endpoints are unchanged. ([#314](https://github.com/ZcashFoundation/zinder/pull/314))
- `ChainEpoch.artifact_schema_version` now reports the artifact schema version (20), the same value as `WalletServerInfo.schema_version`. It previously reported the store layout version (7). ([#316](https://github.com/ZcashFoundation/zinder/pull/316))
- lightwalletd `GetTaddressTxids`, `GetTaddressTransactions`, `GetAddressUtxos`, and `GetAddressUtxosStream` now hold bounded memory however long an address's history is and however many addresses a request lists, and read a repeated address once. `GetAddressUtxos` and `GetAddressUtxosStream` return a repeated address's rows once, as lightwalletd does, instead of once for each time the request lists it. The history calls and `GetAddressUtxosStream` send results as they read them, so a failure after the first result ends the stream with its status after the results already sent; a `GetAddressUtxosStream` response that would exceed 100,000 rows sends the first 100,000 and then ends with `RESOURCE_EXHAUSTED`. ([#317](https://github.com/ZcashFoundation/zinder/pull/317))
- The bundled Grafana overview dashboard now queries the metric names Zinder emits, so its wallet-serving catch-up, replica-lag, refresh, and storage-access panels show data instead of staying empty or reading 0. Re-import `observability/grafana/dashboards/zinder-overview.json` to pick up the fix. ([#321](https://github.com/ZcashFoundation/zinder/pull/321))
