## [0.28.0] - 2026-11-28

**Upgrade class:** `canonical-layout` — Requires a fresh rebuild of the canonical store and dependent projections; see release entries below for layout changes and rollback steps.

### Release Highlights

- **Streamlined Canonical Storage (`Canonical Schema v2` — `ZSHRNG02` + `ZSTSUP01`, [#590](https://github.com/ZcashFoundation/zinder/pull/590), [#594](https://github.com/ZcashFoundation/zinder/pull/594), [#612](https://github.com/ZcashFoundation/zinder/pull/612), [#689](https://github.com/ZcashFoundation/zinder/pull/689), [#717](https://github.com/ZcashFoundation/zinder/pull/717), [#721](https://github.com/ZcashFoundation/zinder/pull/721)):** Unified self-contained canonical store (`CANONICAL_STORE_SCHEMA_VERSION = 2`, `STATE_BUNDLE_FORMAT_VERSION = 2`) sealing settled blocks into `<= 256 MiB` immutable `ZSHRNG02` + `ZSTSUP01` segments with a shared 1,024-entry lazy reader cache and direct v2 range/unary wire splicing; lightwalletd serves ranges directly from canonical segments, removing the external `history-publisher` role, duplicate `ZSHRNG01` catalog storage, `ZINDER_COMPAT__SHIELDED_HISTORY__*` config, and `storage.raw_blob_policy = "transactions"` (leaving only `none` and `all` / `storage.full_blocks = true`). Aligns ADR-0004 and conformance/benchmark tooling ([#685](https://github.com/ZcashFoundation/zinder/pull/685), [#687](https://github.com/ZcashFoundation/zinder/pull/687), [#688](https://github.com/ZcashFoundation/zinder/pull/688)) for future horizontally scalable cloud and PostgreSQL segment-backed reader topologies.
- **Unified `zinder` Binary, Single Distroless OCI Image & Cloud-Native Packaging ([#667](https://github.com/ZcashFoundation/zinder/pull/667)–[#671](https://github.com/ZcashFoundation/zinder/pull/671)):** Consolidates all release executables and 8 legacy container images into one unified `zinder` binary and one non-root distroless OCI image (`ghcr.io/zcashfoundation/zinder`) with Rust supervision, presets (`light-wallet`, `wallet`, `explorer`), `T=0 /healthz`, aggregated `/metrics`, 12-factor `data_dir` and inline TLS/token config, zero-TOML Docker Compose (`zinder-index` + `zinder-serve`), and a Kubernetes RWO `StatefulSet` (`deploy/kubernetes/statefulset.yaml`).
- **Edge Proxy, Transport & Admission Upgrades ([#722](https://github.com/ZcashFoundation/zinder/pull/722), [#724](https://github.com/ZcashFoundation/zinder/pull/724), [#726](https://github.com/ZcashFoundation/zinder/pull/726), [#727](https://github.com/ZcashFoundation/zinder/pull/727), [#730](https://github.com/ZcashFoundation/zinder/pull/730), [#731](https://github.com/ZcashFoundation/zinder/pull/731)):** PROXY protocol v1/v2 from allowlisted TCP proxies (`proxy_protocol_trusted_cidrs`), per-client concurrent block-range stream quotas (default `4`) with optional Tokio scheduling-delay shedding and `grpc-retry-pushback-ms: 250`, HTTP/3 (`h1 h2 h3` + UDP `443`) reference edge proxy, Tor v3 onion service profile, optional OTLP tracing plus reverse-proxy-safe JSON `/status`, and `zinder-client` private TLS roots, pinned server keys, SOCKS5, bounded read retries, and domain-only WASM builds.
- **Breaking Upgrade & Rollback Guidance (`canonical-layout`, [#716](https://github.com/ZcashFoundation/zinder/pull/716)):** Upgrading from `v0.27.x` (Schema v1) requires building a fresh Schema v2 canonical store and dependent projections in a clean path (or restoring a v2 state bundle). Rollback to `v0.27.x` requires preserving a Schema v1 store/backup or rebuilding from empty in a clean path. Operators pulling container images must migrate from the 8 legacy image names to `ghcr.io/zcashfoundation/zinder`.

### Added

- Ship the unified zinder CLI binary supervising role presets (light-wallet, wallet, explorer) and standalone zinder index, zinder run, snapshot, backup, config, and healthcheck subcommands with T=0 /healthz and aggregated /metrics. ([#669](https://github.com/ZcashFoundation/zinder/pull/669))
- Document all scripts in scripts/README.md, add Mermaid system and deployment diagrams across README and overview docs, and align runbooks, reference pages, and ADRs with the unified zinder runtime and Kubernetes StatefulSet. ([#671](https://github.com/ZcashFoundation/zinder/pull/671))
- Support 12-factor data_dir defaults, inline TLS PEM and bearer token values, deployment profiles (light-wallet, wallet, explorer), full_blocks storage toggle, auto-persisted projector owner IDs, and shared multi-role TOML configs. ([#667](https://github.com/ZcashFoundation/zinder/pull/667))
- Require an Upgrade class (compatible, additive-schema, projection-layout, or canonical-layout) on every changelog fragment, derive and render one deterministic Upgrade class header per release starting at v0.28.0, and validate release headers and prerelease archives in scripts/validate-changelog.sh. ([#716](https://github.com/ZcashFoundation/zinder/pull/716))
- The reference Caddyfile explicitly configures `protocols h1 h2 h3`. The TLS runbook covers exposing UDP port 443, verifying HTTP/3, and testing HTTP/2 fallback. CI validates the proxy template. ([#722](https://github.com/ZcashFoundation/zinder/pull/722))
- Serve both wallet gRPC interfaces through a Tor v3 onion service with the reference Compose profile. The runbook covers private home-server access and the metadata each RPC reveals. ([#724](https://github.com/ZcashFoundation/zinder/pull/724))
- Connect zinder-client through private TLS roots and SOCKS5 proxies, verify a pinned server key, and enable bounded retries for read RPCs. Build the domain-only SDK for WebAssembly with default features disabled. ([#726](https://github.com/ZcashFoundation/zinder/pull/726))
- Enable optional OTLP tracing and expose a JSON status summary with readiness, build identity, and served chain heights. ([#727](https://github.com/ZcashFoundation/zinder/pull/727))
- Accept PROXY protocol v1 and v2 on wallet gRPC listeners so trusted TCP load balancers can preserve client addresses. ([#730](https://github.com/ZcashFoundation/zinder/pull/730))
- Limit concurrent wallet block ranges per client and optionally shed new ranges when Tokio scheduling falls behind. Refused calls include gRPC retry pushback. ([#731](https://github.com/ZcashFoundation/zinder/pull/731))

### Changed

- Consolidate release packaging onto the single non-root distroless zinder binary and OCI image, replace legacy shell entrypoints and 18 TOMLs with zero-TOML Compose (zinder-index + zinder-serve), and add a Kubernetes RWO StatefulSet manifest. ([#670](https://github.com/ZcashFoundation/zinder/pull/670))
- Serve ExplorerQuery canonical RPCs and Cipherscan REST routes using RocksDB canonical secondary reads alongside materialized views, and promote block-header selector reads to production readiness. ([#668](https://github.com/ZcashFoundation/zinder/pull/668))
- Cut canonical storage over to Canonical Schema v2 (CANONICAL_STORE_SCHEMA_VERSION = 2) and STATE_BUNDLE_FORMAT_VERSION = 2 ("rocksdb" topology), removed storage.raw_blob_policy = "transactions" (only none and all / storage.full_blocks = true remain), and switched lightwalletd compact-block and nullifier range serving directly to canonical ZSHRNG02 settled segments and live_tail_block while removing the external history-publisher role, duplicate ZSHRNG01 catalog storage, and ZINDER_COMPAT__SHIELDED_HISTORY__* configuration. Upgrading from Schema v1 requires building a fresh Schema v2 canonical store and dependent projections in a clean path (or restoring a v2 state bundle); rollback to v0.27.x requires running the previous release against a preserved Schema v1 store/backup or rebuilding from empty in a clean path. ([#689](https://github.com/ZcashFoundation/zinder/pull/689))
- Stream lightwalletd `GetMempoolTx` responses incrementally when exclusion filters are empty instead of buffering the full mempool snapshot. ([#718](https://github.com/ZcashFoundation/zinder/pull/718))
- Eliminate redundant mempool retention rescans and idle ingest polling on canonical store maintenance paths. ([#720](https://github.com/ZcashFoundation/zinder/pull/720))
- Wire Canonical Schema v2 range and unary compact-block splicing (`ZSHRNG02`, `ZSTSUP01`, and split live-tail wire projection) across `zinder-store`, `zinder-query`, and `zinder-compat-lightwalletd`, eliminating redundant per-block re-encoding on compact-block range and unary reads. ([#721](https://github.com/ZcashFoundation/zinder/pull/721))

### Fixed

- Preserve the configured tip-poll interval, bound canonical event retention pruning work per pass, and yield promptly to canonical maintenance commands while waiting at tip. ([#719](https://github.com/ZcashFoundation/zinder/pull/719))
