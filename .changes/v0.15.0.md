## [0.15.0] - 2026-11-15

### Changed

- Releases now prove their binaries before publishing anything. Both builds of each platform start as soon as the tag is validated, and every release image is packaged from those binaries before the release is approved. Public SDK crates, container images, and the GitHub Release are published only after both builds match. A build, reproduction, or packaging failure no longer leaves a published crate version without matching binaries. ([#206](https://github.com/ZcashFoundation/zinder/pull/206))
- Explorer views now keep per-height undo rows only for the reorg window, and ingest deletes older undo rows from an existing view store when it opens it, without a rebuild. New transparent-address delta and activity rows store each transaction id as 32 bytes instead of 64 hex characters, while rows already written keep reading. On a transparent-heavy fixture the two changes cut view storage by 41%. Rolling back to an earlier release requires rebuilding the Explorer views, because earlier releases read the rows this release writes with an empty transaction id. ([#208](https://github.com/ZcashFoundation/zinder/pull/208))

### Fixed

- A transparent-address ranking build that trails Explorer views still rebuilding from canonical history now catches up and joins them, instead of falling further behind until replay reaches the tip, so address detail and activity return far sooner on read-limited storage. View replay waits for such a build while `zinder_materialized_view_replay_waiting_for_ranking_build` is `1`, and stops waiting if the build applies no history for 5 minutes. Spend resolution also issues fewer device reads, the prevout resolution metrics gain a `cache` label that names the walker, and `zinder-ingest` exports its canonical reader's RocksDB gauges under the `canonical_secondary` store role. ([#209](https://github.com/ZcashFoundation/zinder/pull/209))
