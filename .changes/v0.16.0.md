## [0.16.0] - 2026-11-16

### Changed

- Wallet serving now publishes a new block within about 1.25 seconds of its canonical commit instead of 10 to 28 seconds, because `zinder-query` reuses a serving generation that no request holds instead of opening new secondaries for every publication. Drained generations stay open and are reused in turn, so each keeps the primary files it references for only a few blocks after compaction replaces them. New metrics `zinder_wallet_serving_pair_publisher_candidate_prepared_total` and `zinder_wallet_serving_pair_publisher_cold_open_duration_seconds` show how often a cold open still happens. ([#223](https://github.com/ZcashFoundation/zinder/pull/223))
- Zinder now bundles RocksDB 11.12 through rust-rocksdb 0.54, which fixes a secondary reader serving stale values from write-ahead log entries the primary already flushed and secondary catch-up that slowed with file count. Stores written by v0.15.1 open unchanged and v0.15.1 reads canonical and wallet stores written by this version. The `tickers` statistics level now collects tickers only and no longer records size histograms. ([#225](https://github.com/ZcashFoundation/zinder/pull/225))

### Fixed

- Canonical construction again cross-checks every tree-state checkpoint it writes: if a checkpoint's encoding does not match the note-commitment tree that construction built, `zinder-ingest` stops before publishing the store. Since v0.15.1 only the build-tip checkpoint was compared. Live following is unchanged. ([#219](https://github.com/ZcashFoundation/zinder/pull/219))
- A wallet transition over `projector.follow.max_transition_logical_bytes` no longer makes `zinder-projector` exit and restart in a loop. The projector stays up and reports the new readiness cause `wallet_transition_limit_exceeded` with the configured limit and a lower bound on the bytes required, keeps its retention lease, and retries only when the transition changes. The single-volume images keep the container running and their healthcheck passing while it is parked; raise the setting and restart to resume. The readiness protocol gains the cause and its detail message. ([#224](https://github.com/ZcashFoundation/zinder/pull/224))
