## [0.21.0] - 2026-11-20

### Changed

- Explorer replay reuses the final note-commitment roots of checkpointed blocks. It reads compact blocks and hashes commitments only for gaps. If replay stalls on invalid canonical data, ingest continues checking settled checkpoints and reports confirmed damage through WriterStatus. ([#427](https://github.com/ZcashFoundation/zinder/pull/427))

### Fixed

- The RocksDB storage lifecycle harness now accepts benchmark reports from canonical store schema 7. ([#419](https://github.com/ZcashFoundation/zinder/pull/419))
- Wallet supervision now applies the one-hour tolerance and recurrence budgets when ingest stalls preparing a block. If a mempool node outage continues through brief canonical lags, its 24-hour clock pauses and resumes with the time already spent waiting. Rust callers constructing syncing details must account for the new optional wait_reason field. ([#420](https://github.com/ZcashFoundation/zinder/pull/420))
- Wallet ChainEvents subscribers on the Settled family receive each newly settled block range and can resume from a cursor anchored at its last settled block. Settled subscriptions with the Rust client require a server advertising contract revision 12 or later. ([#421](https://github.com/ZcashFoundation/zinder/pull/421))
- Live mempool reads now return `NODE_UNAVAILABLE` after an endpoint switch or when a replacement takes more than 30 seconds to certify. Retained events remain replayable, and a later certification restores live reads. Native wallet queries now receive `STORAGE_UNAVAILABLE` when the ingest store owner stalls during a mempool read or subscription setup. Upgrade the writer and query together for native contract revision 13. ([#422](https://github.com/ZcashFoundation/zinder/pull/422))
- The Explorer gRPC listener now serves health and reflection while unready, and refuses new Explorer queries until readiness recovers. A failed background task or operational endpoint stops Explorer with exit 1 and names the task. At the shutdown drain deadline, open calls receive `UNAVAILABLE` with the `shutting_down` cause. ([#423](https://github.com/ZcashFoundation/zinder/pull/423))
- Ingest reports a protocol mismatch when a node repeats a reply ID in a batched `getblock` response. A missing reply no longer causes ingest to retry that height as unavailable. ([#424](https://github.com/ZcashFoundation/zinder/pull/424))
- Background tree-state verification detects damage to a canonical block header's table file even after an earlier pass read the header successfully. ([#425](https://github.com/ZcashFoundation/zinder/pull/425))
- Explorer advertises ValuePoolSummary only when the connected wallet endpoint supports it. It omits MempoolEventCounts and ValuePoolBalanceHistory from discovery. An empty event-count window is reported as unavailable in OverviewSnapshot and returns ARTIFACT_UNAVAILABLE on a direct call. For native contract revision 14, upgrade zinder-ingest, zinder-query, and wallet-mode zinder-compat-lightwalletd together. Both readers require a matching writer revision. ([#428](https://github.com/ZcashFoundation/zinder/pull/428))
- Historical wallet tree-state reads use less CPU when Zinder rebuilds a frontier between stored checkpoints. ([#430](https://github.com/ZcashFoundation/zinder/pull/430))
- On shutdown, zinder-compat-lightwalletd interrupts pending writer-status reads and catch-up retries in compact-blocks mode, keeping the published reader and skipping refresh-failure reporting. In-flight RocksDB work and closing secondaries can extend shutdown beyond the wallet-serving entrypoint's 20-second grace window. ([#431](https://github.com/ZcashFoundation/zinder/pull/431))
- Ingest and Explorer now default to the projector's canonical store directory, `/var/lib/zinder/canonical`. If your store is at the old default, set `ZINDER_STORAGE__PATH=/var/lib/zinder/store` for ingest and Explorer before upgrading. Set `ZINDER_STORAGE__CANONICAL_PATH=/var/lib/zinder/store` for a projector that reads that store. ([#432](https://github.com/ZcashFoundation/zinder/pull/432))
- Compact-blocks serving can start and stay ready at a matching canonical fence when ingest omits the upgrade schedule or reports a different revision. ([#433](https://github.com/ZcashFoundation/zinder/pull/433))
- The projector reports which startup operation failed when it opens a wallet, checks the writer fence, or binds its control listener. If ingest is unavailable when a cancelled wallet build releases its retention lease, the projector logs the expiry and completes shutdown. ([#434](https://github.com/ZcashFoundation/zinder/pull/434))
