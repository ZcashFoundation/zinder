## [0.29.0] - 2026-11-28

**Upgrade class:** `canonical-layout` — Requires a fresh rebuild of the canonical store and dependent projections; see release entries below for layout changes and rollback steps.

### Release Highlights

- **Upgrade & Rollback Summary (`v0.28.0` → `v0.29.0`, [#742](https://github.com/ZcashFoundation/zinder/pull/742), [#750](https://github.com/ZcashFoundation/zinder/pull/750), [#764](https://github.com/ZcashFoundation/zinder/pull/764)):** Forward upgrades from `v0.28.0` open existing Schema v2 canonical stores **in place** (no full canonical reindex is required); only the **wallet projection** requires a fresh rebuild in a clean path from the canonical store ([#742](https://github.com/ZcashFoundation/zinder/pull/742)). This release retains the `canonical-layout` upgrade class because [#750](https://github.com/ZcashFoundation/zinder/pull/750) (construction manifest checkpoint policy) and [#764](https://github.com/ZcashFoundation/zinder/pull/764) (`ZSLVTL01` live-tail fee-width flags) write canonical metadata and live-tail rows that `v0.28.0` rejects, so **rolling back to `v0.28.0`** after incompatible writes requires restoring a pre-upgrade backup/snapshot or rebuilding the canonical store and dependent projections in clean paths.
- **Strict Unified Configuration & Orchestration Split ([#755](https://github.com/ZcashFoundation/zinder/pull/755), [#758](https://github.com/ZcashFoundation/zinder/pull/758), [#759](https://github.com/ZcashFoundation/zinder/pull/759), [#766](https://github.com/ZcashFoundation/zinder/pull/766)):** Replaces `config-rs` with a type-directed TOML/Serde loader across one strict 18-section `ZinderConfig` schema (preserving exact secret bytes, rejecting empty values and `[REDACTED]` placeholders in favor of `"none"`, unifying canonical paths on `storage.path` and `storage.secondary_path`, and planning/validating child role configurations in memory). Separates `DEPLOY_*` Compose/systemd/Caddy variables (`deploy/profiles/<network>/deploy.env`) from `ZINDER_*` runtime settings (`zinder.env`), aligns `deploy/personal/compose.yaml`, wires `DEPLOY_X86_64_CPU_BASELINE`, exposes port `9105`, and enforces profile `config validate` and fail-closed unknown-key smokes in OCI image builds.
- **Wallet Protocol, SDK & Ecosystem Tooling ([#723](https://github.com/ZcashFoundation/zinder/pull/723), [#729](https://github.com/ZcashFoundation/zinder/pull/729), [#733](https://github.com/ZcashFoundation/zinder/pull/733)–[#736](https://github.com/ZcashFoundation/zinder/pull/736), [#738](https://github.com/ZcashFoundation/zinder/pull/738)–[#740](https://github.com/ZcashFoundation/zinder/pull/740), [#749](https://github.com/ZcashFoundation/zinder/pull/749), [#760](https://github.com/ZcashFoundation/zinder/pull/760)):** Adds native gRPC-Web on `WalletQuery`/`ExplorerQuery`, gzip/zstd gRPC message compression with retry pushback, epoch-pinned descending/pool-filtered compact scans, shielded nullifier streams, transparent address batches, verified recommended fees, and height-aligned `GetAddressUtxos` pagination across `zinder-proto`, `zinder-query`, and `zinder-client`. Ships `zinder dev darkside` with generated `zinder-proto` Darkside bindings and versioned standalone protobuf contract archives.
- **Host Packaging & Native `systemd` Units ([#728](https://github.com/ZcashFoundation/zinder/pull/728), [#751](https://github.com/ZcashFoundation/zinder/pull/751)):** Adds verified release archives for Apple Silicon (`aarch64-apple-darwin`) and baseline/v3 Linux hosts, a personal-node Compose bundle, and hardened native `systemd` units with loopback-only defaults and VM runbooks inside GNU/Linux archives (`systemd` 254+).
- **Storage Footprint & Read Performance ([#742](https://github.com/ZcashFoundation/zinder/pull/742), [#750](https://github.com/ZcashFoundation/zinder/pull/750), [#752](https://github.com/ZcashFoundation/zinder/pull/752)–[#754](https://github.com/ZcashFoundation/zinder/pull/754), [#756](https://github.com/ZcashFoundation/zinder/pull/756), [#762](https://github.com/ZcashFoundation/zinder/pull/762), [#764](https://github.com/ZcashFoundation/zinder/pull/764)):** Introduces wallet projection RocksDB Schema v2 for a smaller on-disk footprint, records checkpoint policy in canonical construction manifests, encodes `ZSLVTL01` fee-width flags with per-`READY` live-tail caching, caches settled supplement chunks, adds settled-segment page-cache bounding and I/O/cache metrics, and hardens secondary live-tail catch-up recovery.

### Added

- Run Zinder on Apple Silicon and older x86-64 Linux hosts with verified release archives, or run a private light-wallet stack with the personal-node Compose bundle. ([#728](https://github.com/ZcashFoundation/zinder/pull/728))
- Enable native binary and text gRPC-Web on WalletQuery and ExplorerQuery by setting browser origins on each listener. List specific origins when ExplorerQuery requires a bearer token. Settled WalletQuery event streams expose their family header to browser clients. ([#729](https://github.com/ZcashFoundation/zinder/pull/729))
- Wallet and explorer gRPC clients can negotiate gzip or zstd message compression. Admission and readiness refusals include retry pushback guidance. ([#733](https://github.com/ZcashFoundation/zinder/pull/733))
- Define native wallet protocol requests for descending and pool-filtered compact scans, shielded nullifiers, the recommended fee, and transparent address batches. ([#734](https://github.com/ZcashFoundation/zinder/pull/734))
- Serve native wallet scan and transparent address batches at one chain epoch. Query operators can keep observed epoch pins readable for 60 to 300 seconds after replacement. ([#735](https://github.com/ZcashFoundation/zinder/pull/735))
- Add typed Rust client calls for compact scans, nullifier streams, transparent address batches, and the verified recommended fee. ([#736](https://github.com/ZcashFoundation/zinder/pull/736))
- Paginate GetAddressUtxos and GetAddressUtxosStream at complete block heights within maxEntries. If the first height exceeds maxEntries, retry with the count from MAX_ENTRIES_EXCEEDED_AT_HEIGHT. In light-wallet serving, 100,000 outputs at the first height followed by more matching outputs can fail with RESOURCE_EXHAUSTED because the node lookup cannot end at that height. ([#738](https://github.com/ZcashFoundation/zinder/pull/738))
- Run zinder dev darkside in wallet SDK CI to script compact-block sync, reorgs, and transaction broadcasts over gRPC or gRPC-Web without a Zcash node. ([#740](https://github.com/ZcashFoundation/zinder/pull/740))
- Add the generated Darkside test-control client and server and DARKSIDE_FILE_DESCRIPTOR_SET to zinder-proto for wallet SDK testing. ([#739](https://github.com/ZcashFoundation/zinder/pull/739))
- Publish versioned, standalone protobuf contracts and full descriptor sets in signed release API archives so downstream consumers can pin schemas and generate clients without cloning Zinder. ([#749](https://github.com/ZcashFoundation/zinder/pull/749))
- Record the resolved tree-state checkpoint policy in the canonical construction manifest and surface it in READY logs and store-properties reports. Pre-change stores remain readable in place, while older binaries reject newly built manifests; to roll back, restore a pre-change store or backup, or rebuild the canonical store and dependent projections in clean paths with the previous release. ([#750](https://github.com/ZcashFoundation/zinder/pull/750))
- GNU/Linux release archives include hardened native systemd units, loopback-only defaults, and VM deployment guidance for running Zinder wallet and opt-in Explorer services directly on hosts with systemd 254 or newer. ([#751](https://github.com/ZcashFoundation/zinder/pull/751))
- Expose Prometheus metrics for settled-segment reader cache residency, cache hits and evictions, and positional file I/O attributed by segment kind, along with RSS attribution guidance. ([#753](https://github.com/ZcashFoundation/zinder/pull/753))

### Changed

- Bump the wallet projection RocksDB store to schema v2 (adding block_hash_by_height, compacting transparent output and address-history row encodings, and tuning per-CF compression and block sizes) to reduce on-disk footprint; upgrading the wallet projection requires a fresh rebuild in a clean path from the canonical store, and rollback requires restoring a prior v1 wallet snapshot or rebuilding with the previous release. ([#742](https://github.com/ZcashFoundation/zinder/pull/742))
- Bound settled-segment page-cache churn under constrained cgroup memory budgets using Linux readahead and drop-behind hints, expose corpus-vs-budget startup warnings and metrics, and amend ADR-0005. ([#754](https://github.com/ZcashFoundation/zinder/pull/754))
- Replace `config-rs` with a type-directed TOML and Serde configuration loader so secret strings preserve exact bytes, invalid scalar coercions fail closed, and mistyped `ZINDER_*` environment variables report typo suggestions. ([#755](https://github.com/ZcashFoundation/zinder/pull/755))
- Unify all runtimes and the `zinder` supervisor onto one strict 18-section `ZinderConfig` schema, reject empty values and `[REDACTED]` placeholders in favor of `"none"`, unify canonical paths on `storage.path` and `storage.secondary_path`, and plan and validate child role configurations in memory. ([#758](https://github.com/ZcashFoundation/zinder/pull/758))
- Separate `DEPLOY_*` Compose, systemd, and Caddy orchestration variables in `--env-file deploy/profiles/<network>/deploy.env` from `ZINDER_*` runtime settings passed via `env_file:` in `deploy/profiles/<network>/zinder.env`, and remove the legacy combined `deploy/.env.*` files. ([#759](https://github.com/ZcashFoundation/zinder/pull/759))
- Encode ZSLVTL01 fee-width header flags (bits 3 and 4) on unsealed live-tail rows and cache validated live-tail compact blocks per READY generation in canonical secondary readers. New releases open existing Schema v2 stores in place; rolling back to a release predating these flags requires restoring a pre-upgrade backup or snapshot, or rebuilding the canonical store and dependent projections in clean paths. ([#764](https://github.com/ZcashFoundation/zinder/pull/764))
- Pass `DEPLOY_X86_64_CPU_BASELINE` (`x86-64-v3` default) to `zinder-bench-binary`, expose port `9105` in the container image, align `deploy/personal/compose.yaml` with `DEPLOY_*` orchestration variables, `ZINDER_DEPLOYMENT__PROFILE=light-wallet`, and dual-stack container listeners, and enforce `dev darkside --help`, profile `config validate`, and fail-closed unknown-key smoke checks in OCI image builds. ([#766](https://github.com/ZcashFoundation/zinder/pull/766))

### Fixed

- Run disposable wallet Regtest fixtures on macOS and Windows with Docker Desktop or on native Linux with Docker Engine. ([#723](https://github.com/ZcashFoundation/zinder/pull/723))
- Reuse canonical protobuf payloads on unary GetBlock and GetBlockNullifiers responses, cache verified settled supplement Zstd chunks under a shared byte budget, and avoid redundant range-read recounts. ([#752](https://github.com/ZcashFoundation/zinder/pull/752))
- Scan settled canonical replay headers sequentially from RocksDB, reconstruct settled replay directly from authenticated supplement chunks without decoding unused compact blocks, and align replay batches to 256 blocks. ([#756](https://github.com/ZcashFoundation/zinder/pull/756))
- Include the vendored Darkside test-control schema in the standalone protobuf contract archive's Buf workspace, combined descriptor, and archive verification checks. ([#760](https://github.com/ZcashFoundation/zinder/pull/760))
- Recover RocksDB secondary catch-up and projector replay when an advancing READY fence briefly misses a live_tail_block row, using a bounded reopen with continuity and network-upgrade attestation checks. ([#762](https://github.com/ZcashFoundation/zinder/pull/762))
